# IslandTray 第 2 ラウンド 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 実機で使ってみて出た 5 件の要望に対応する。

**Architecture:** 既存の構成は変えない。`TraySettings` を新設して 2 つの設定項目を持たせ、Live Activity の `ContentState` に小さなサムネイルとファイル名を載せ、取り出し時に項目を消す経路を足し、アプリアイコンを作る。

**Tech Stack:** Swift 6 / SwiftUI / ActivityKit / WidgetKit / AppIntents / QuickLookThumbnailing / XCTest

第 1 ラウンドの計画: [`2026-09-18-island-tray.md`](2026-09-18-island-tray.md) — ただし **Task 5 の `TrayStore` コードは使ってはならない**（同ファイル冒頭の警告を読むこと）。

## この計画の書き方について

第 1 ラウンドの計画は各タスクに完成コードを載せたが、レビューでそのコードから Critical 8 件・Important 20 件超が見つかり、ほぼ全てが書き直しになった。**この計画は要件と制約だけを書き、実装は各タスクの担当に委ねる。** 代わりにテストと変更禁止事項を厳しく指定する。

## Global Constraints

- iOS 17.0 / Swift 6 strict concurrency。`@unchecked Sendable` / `@preconcurrency` / `nonisolated(unsafe)` は**禁止**。必要だと判断したら使わずに報告すること。
- コード内のコメントは**英語**。日本語はユーザー向け文字列のみ。
- 新しい依存を追加しない。`#if` による有料・無料の分岐を作らない。
- バンドル ID は変更しない（無料アカウントは週あたりの App ID 発行数に上限がある）。
- `ContentState` のエンコード後サイズは **4096 バイト未満**。これは ActivityKit の実際の上限で、超えると Live Activity が開始も更新もできない。
- `Sources/Shared/TrayStore.swift` はレビュー 4 ラウンドで 15 件の欠陥を閉じたファイル。触る必要が出たら、その回で守るべき保証を明示したうえで作業すること。
- テストは XCTest のみ。**追加したテストは必ず変異検証する** —— 対象のロジックを壊してテストが落ちることを確認する。このプロジェクトでは「対象を消しても通るテスト」が 5 回出荷された。
- 実機は iPhone 16 Pro / iOS 27、配布は SideStore。**App Group は SideStore の再署名を通らない**ことが実機で判明済み（共有拡張が「有料アカウントのみ」と表示した）。したがって無料構成が実際の動作環境である。

## Task 1: 設定の受け皿と「空でも表示」

**要件**

1. `TraySettings` を新設する。`UserDefaults` に保存し、アプリ本体と Widget Extension の両方から読めること。App Group が無い環境が本番なので、**Widget から読めない場合の既定値が正しく効く**ようにする。
2. 設定項目その 1: **トレイが空のときも Live Activity を表示するか**。既定は **表示する**。
3. 現状 `TrayActivityController.sync(items:)` は項目が 0 件になると `end()` する。設定が「表示する」の間は、空でも件数 0 の状態で表示を維持すること。
4. アプリが起動したら、トレイが空でも Live Activity を開始すること（ユーザーの要望は「アプリがバックグラウンドで生きている限り出ていてほしい」）。
5. 設定が「表示しない」に切り替わった瞬間、トレイが空なら表示を終了すること。逆に「表示する」へ切り替えたら、空でも開始すること。
6. `SetupGuideView` に両方の設定のトグルを置く。文言は既存の日本語のトーンに合わせる。

**守ること**

- `end()` / `restart()` / `isLive` の既存の振る舞いを壊さない。特に「8 時間で終了した activity を更新し続けない」「`restart()` は置き換えが出来てから古いものを退役させる」の 2 点。
- 空表示の維持は `Activity.request` の呼び出し回数を増やす方向に倒さないこと。8 時間の枠は `restart()` が管理している。

**テスト**

- 設定の既定値、読み書き、Widget 側から読めないときのフォールバック。
- 「空 + 表示する」「空 + 表示しない」「非空」の 3 状態で `sync` が開始・維持・終了のどれを選ぶかを固定する。ActivityKit を起動せずに判定部分だけ切り出せるなら切り出して固定すること。

## Task 2: アイランド内に実サムネイルとファイル名を出す

いまアイランドの展開表示はコンテナ上のサムネイル画像ファイルを読もうとするが、App Group が無いと読めないので SF Symbol に落ちる。実機がまさにその状態で、ユーザーからは「写真アイコンしか出ない」と見えている。ファイル名も `Preview` が持っていないので出ない。

**要件**

1. `ContentState` に**小さな JPEG サムネイル本体**と**表示名**を載せ、Widget プロセスがコンテナを読めなくても実画像と名前を出せるようにする。
2. **4096 バイトの上限を絶対に超えないこと。** 超えると Live Activity が丸ごと動かなくなる。載せられる分だけ載せ、入らない分は従来どおり SF Symbol に落ちること。何件・どの解像度なら入るかは**実測して決める** —— 見積もりで決めないこと。
3. サムネイルの寸法と JPEG 品質は、アイランド展開表示での見え方（1 辺 40pt 程度）に対して妥当な範囲で選ぶ。多少粗くても、汎用アイコンよりは情報量が多いという判断。
4. ファイル名はアイコンの下に 1 行で、長ければ中略して出す。アプリ内のカードと同じ扱い。
5. App Group が使える環境では従来どおりコンテナ上の高解像度サムネイルを優先してよい。ただし**無料構成が本番**なので、そちらを主経路として作ること。
6. 写真・動画・アルバムアートを持つ音源で実際にサムネイルが得られることを確認する。`QLThumbnailGenerator` が返さない種類があれば報告する。

**守ること**

- `TrayContentState` の初期化子は private のまま。`make(from:)` と `countOnly(count:)` 以外の生成経路を増やさない。
- `Codable` のデコード側も上限内に収まること。デコードはサイズ超過で throw してはならない（Widget プロセスでの失敗は Live Activity の消失を意味する）。
- 既存の `TrayContentStateTests` を弱めないこと。

**テスト**

- 最悪ケース（最大件数 × 最長の名前 × 最大サイズのサムネイル）でエンコード後サイズが 4096 未満であること。**この種のテストは過去に「実際には最悪ケースになっていない」不具合を出しているので、何が最悪なのかを根拠付きで示すこと。**
- 予算を超える入力で、件数が減るか SF Symbol に落ちるかして、必ず上限内に収まること。
- デコードがどんな入力でも throw しないこと。

## Task 3: 取り出しは「移動」、設定で切り替え

ユーザーの意図は「トレイは切り取りバッファ」。他アプリへ渡したらトレイからは消えるのが既定。

**注意:** 取り込み側（他アプリからトレイへ入れるとき）に元を消す動作は iOS では実装できない。`UIDropOperation.move` はアプリ内専用と Apple が明記している。本タスクは**取り出し方向のみ**。

**要件**

1. 設定項目その 2: **取り出したらトレイから消すか**。既定は **消す（移動）**。
2. カードを他アプリへドラッグして渡した場合、渡が成立したらトレイから項目を削除する。**成立しなかったドラッグ（途中で離した、受け取り側が拒否した）では削除しないこと。** ここを取り違えるとユーザーのファイルが消える。
3. 共有シート経由で渡した場合も同様に扱う。ただし共有シートは結果を返さないことがあるため、**成功が確認できない限り削除しないこと**。確認できない場合の扱いを報告すること。
4. 設定が「残す」のときは現状どおり削除しない。
5. 削除は既存の `remove(id:)` を通すこと。`TrayRemovalResult` の部分失敗はユーザーに見える形で扱う（このコードベースの既存方針に合わせる）。

**守ること**

- トレイはユーザーの**唯一のコピー**を持ちうる。削除はドラッグが実際に成立したと確認できたときだけ。迷ったら消さない。
- `TrayStore` の既存の保証、特に「削除した項目はリビルドで復活しない」「throw した `add` は痕跡を残さない」を壊さないこと。

**テスト**

- 「移動 ON + ドラッグ成立」「移動 ON + ドラッグ不成立」「移動 OFF」の 3 状態で削除されるかどうかを固定する。ドラッグ成立の判定部分が UIKit から切り離せるなら切り出して固定すること。

## Task 4: アプリアイコン

**要件**

1. 1024×1024 のアプリアイコンを作り、`Resources/App/Assets.xcassets/AppIcon.appiconset` に入れる。
2. モチーフはトレイ（受け皿）。ダイナミックアイランドの横長の黒いピル形を想起させる形を絡めてよい。**内容が読み取れる程度に単純**であること —— ホーム画面での実寸は 60pt 程度で、細部は消える。
3. 角丸は付けないこと（iOS が自動で丸める）。透明部分を持たないこと。
4. 生成方法は問わないが、**リポジトリ内で再生成できること**。スクリプトか、ソースとなるベクタを一緒にコミットする。外部サービスに依存しないこと。
5. 実際にシミュレータへインストールして、ホーム画面でどう見えるかを確認すること。潰れて判別できないなら作り直す。

**守ること**

- 実在の企業・製品のアイコンやロゴに似せないこと。
- ビルドが通り、アイコン警告が出ないこと。
